# Jarvis — версия 2.9.0

## Что исправлено в 2.9.0

- DeepSeek стал основным текстовым провайдером. Mistral и резервный AI
  используются только если DeepSeek не ответил; модели можно переопределить
  через `DEEPSEEK_MODEL`, `MISTRAL_MODEL` и `AI_MODEL`.
- Ответ нейросети больше не может замаскировать неудачный запуск приложения:
  при ошибке пользователь услышит точную причину.
- Запуск Windows-приложений теперь проверяет несколько источников: известные
  пути установки, ярлыки меню «Пуск», Microsoft Store и зарегистрированные
  приложения. Добавлены отдельные обработчики для Discord, Telegram, Chrome,
  Edge, Visual Studio Code и Visual Studio.
- Распознавание речи больше не обрывается после короткой паузы: стандартное
  окно фразы увеличено до 18 секунд, пауза — до 1,05 секунды. Значения можно
  изменить через `JARVIS_PHRASE_TIME_LIMIT` и `JARVIS_PAUSE_THRESHOLD`.
  Добавлено мягкое распознавание вариантов слова «Джарвис» вроде «Жарвис».
- Значки закрытия и сворачивания главного окна уменьшены примерно в 1,5 раза.

Ассистент не выполняет произвольный код, сгенерированный моделью. Системные
действия проходят через безопасный локальный маршрутизатор, а DeepSeek
используется для диалога, текста и кода. Это не даёт модели объявить
приложение открытым, если Windows фактически его не запустила.

В предыдущих версиях был добавлен стилизованный аккаунт лаунчера. При первом запуске
пользователь создаёт профиль по email, никнейму и паролю, а затем подтверждает
email шестизначным кодом. В боковом меню появилась кнопка **Аккаунт** и экран
PRO без подключения оплаты: кнопка оформления уже подготовлена, а срок
подписки будет показываться после добавления платёжного сервиса.

Для настоящей отправки кодов через email можно настроить один из вариантов:

```env
# Вариант 1: ваш backend с POST /api/auth/send-code
JARVIS_AUTH_URL=https://ваш-домен.example

# Вариант 2: SMTP
JARVIS_SMTP_HOST=smtp.example.com
JARVIS_SMTP_PORT=587
JARVIS_SMTP_USER=почта@example.com
JARVIS_SMTP_PASSWORD=пароль_почты
JARVIS_SMTP_FROM=почта@example.com
```

Для входа с другого компьютера нужен `JARVIS_AUTH_URL`: лаунчер использует
ваш backend для `POST /api/auth/send-code`, `POST /api/auth/register` и
`POST /api/auth/login`. Backend должен хранить пользователей по email и
проверять код подтверждения; локальное сохранение используется как резервный
режим без сервера и действует только на этом устройстве.

Если почтовая отправка не настроена, приложение остаётся полностью
работоспособным в локальном режиме и показывает код непосредственно в форме
регистрации. Это удобно для проверки сборки; для пользователей рекомендуется
настроить `JARVIS_AUTH_URL` или SMTP до публикации.

В версии 2.8.2 основное распознавание речи переведено на Groq Whisper
(`whisper-large-v3-turbo`). Аудио перед отправкой переводится в моно WAV
16 кГц, запрос получает русский язык и подсказку с именами приложений и
ключевым словом. Если Groq временно недоступен или ключ неверный, Jarvis
автоматически использует Google Speech Recognition как резервный вариант.

В версии 2.8.1 исправлено применение обновлений: отдельный внешний установщик
распаковывает ZIP после закрытия Jarvis, заменяет файлы и запускает новую
версию. Во время скачивания показывается прогресс. В версии 2.8.0 приватный
локальный `.env` автоматически шифруется и встраивается
в `_internal` во время сборки. Railway теперь является только опциональным
fallback, поэтому локальная сборка не должна ждать Railway. Также список микрофонов
скрывает дубликаты и типичные виртуальные устройства. В версии 2.6.7 сборщик
снова автоматически добавляет локальный
`jarvis_secrets.dat`, если он лежит рядом с `build_windows.bat`. В версии 2.6.6
исправлена загрузка приватного `.env`, если он лежит рядом с
`Jarvis.exe`. Версия теперь отображается в шапке лаунчера. Также увеличены
зоны нажатия кнопок закрытия и сворачивания окна,
а также добавлен онлайн-голос «Акаши Сейджеро».

## Автоматические обновления

Лаунчер проверяет GitHub Releases примерно через секунду после запуска. Если
версия новее текущей и в релизе есть ZIP-файл, пользователь увидит уведомление.
После согласия архив скачивается, Jarvis закрывается, файлы заменяются и
программа запускается снова. `jarvis.db` и `.env` при обновлении сохраняются.
В публичный архив секреты не входят: задавайте ключи через переменные
окружения или серверный backend.

Перед первой сборкой проверьте `gogosha11/Jarvis` в
`build_windows.bat` и в начале `launcher.py`.
Каждое обновление выпускайте новым тегом вида `v2.6.4`, а в релиз прикладывайте
файл `dist\Jarvis-windows.zip` (его создаёт build-скрипт).

В лаунчере на странице **Настройки** добавлены:

- поле **Ключевое слово** — по умолчанию `Джарвис`; после сохранения ассистент
  реагирует на указанное слово;
- список голосов для сгенерированных ответов: Джарвис, Мита, Мариарти, Рик,
  Морти, Губка Боб и Акаши Сейджеро;
- флажок **Использовать характер выбранного голоса** — меняет стиль ответов
  под персонажа; без флажка все голоса отвечают стандартно;
- предупреждение о том, что дополнительные голоса доступны только онлайн.

Настройки сохраняются в Windows `QSettings` и передаются голосовому модулю
только при следующем запуске прослушивания.

## `.env`

Для улучшенного распознавания речи добавьте ключ Groq:

```env
GROQ_API_KEY=ваш_ключ_из_console.groq.com
```

По умолчанию используется быстрая модель `whisper-large-v3-turbo`. Для
максимальной точности можно выбрать более медленную модель:

```env
GROQ_WHISPER_MODEL=whisper-large-v3
```

Для выбора приоритета текстовых моделей:

```env
DEEPSEEK_MODEL=deepseek-chat
MISTRAL_MODEL=mistral-small-latest
AI_MODEL=gpt-4o-mini
JARVIS_PHRASE_TIME_LIMIT=18
JARVIS_PAUSE_THRESHOLD=1.05
```

`DEEPSEEK_API_KEY` используется первым, затем `MISTRAL_API_KEY`, затем
`AI_API_KEY` как резерв. Секунды и время фразы можно увеличить, если вы
говорите длинными предложениями; для обычной речи значения по умолчанию уже
увеличены против предыдущей версии.

Ключ `PROVOD_API_KEY` не требуется для распознавания речи: Provod.ai
предоставляет OpenAI-совместимый API для текстовых моделей, а транскрибацию
здесь выполняет отдельный endpoint Groq Whisper.

Для локального базового голоса Джарвиса новый ключ не нужен.

Для голосов Миты, Мариарти, Рика, Морти и Губки Боба нужен уже используемый
ключ Fish Audio:

```env
FISH_AUDIO_API_KEY=ваш_ключ
```

Если ключ уже настроен в текущей сборке, добавлять ничего не требуется:
ID выбранного голоса лаунчер передаст автоматически. `FISH_AUDIO_REFERENCE_ID`
можно оставить как есть — он используется для базового голоса Джарвиса и
обратной совместимости. Не добавляйте секреты в архив или публичный репозиторий.

Для локальной проверки положите `.env` рядом с `Jarvis.exe` после сборки. Не
загружайте его в GitHub и не включайте в ZIP релиза: любой пользователь сможет
извлечь API-ключи из такого архива.

В исходных вложениях к этому проекту были обнаружены заполненные ключи и
пароль SMTP. Перед дальнейшим использованием замените эти ключи у провайдеров
и обновите локальный `.env`; в этот исправленный архив секреты намеренно не
включены.

Для естественных реплик после действий и характеров также должен быть настроен
один из используемых AI-ключей (`AI_API_KEY`, `DEEPSEEK_API_KEY` или
`MISTRAL_API_KEY`). Без AI-ключа действие всё равно выполнится, но ответ будет
резервным техническим сообщением.

## Сборка с ключами без загрузки их в GitHub

Положите `.env` рядом с `build_windows.bat`, а также добавьте папку `voise`.
Запустите `build_windows.bat`: он сам создаст временный зашифрованный
`jarvis_secrets.dat`, встроит его в `_internal`, а затем удалит этот файл из
исходной папки. В GitHub `.env` и `jarvis_secrets.dat` не загружайте.

Полученный `dist\Jarvis-windows.zip` будет содержать ключи внутри `_internal`,
поэтому такой архив предназначен только для личного использования или доверенных
друзей: встроенные ключи технически можно извлечь.

## Railway backend

Сайт из архива `website_release` может оставаться backend. Если задать
`JARVIS_BACKEND_URL`, Jarvis использует его как fallback. В Railway добавьте
ключи Variables: `AI_API_KEY`, `DEEPSEEK_API_KEY`,
`MISTRAL_API_KEY`, `GROQ_API_KEY`, `FISH_AUDIO_API_KEY` и
`FISH_AUDIO_REFERENCE_ID`.
Jarvis по умолчанию обращается к
`https://website-jarvis-production.up.railway.app`. Для другого домена
измените `JARVIS_BACKEND_URL` в `app.py` перед сборкой.
